# 三步 · AI 真实任务卡

> 把「帮我把这个弄好一点」变成一张 AI 一次就能执行到位的任务卡，并在交付前完成两道核验。

一个可直接安装使用的 Agent Skill。出自一条 72 秒的口播视频，本仓库把视频里一句话带过的规则，补成了定义、判定标准、追问话术、可复制清单、跨场景示例和一个校验脚本。

**核心立场：AI 不替你思考，只帮你更快做出第一版。**

---

## 这个方法解决什么

大多数「AI 不好用」不是模型的问题，是信息给得不全、限制写成了愿望：

- 只说「整理一下」，没说给谁看、要什么格式 → AI 只能猜。
- 写「更美观」「更准确」「专业一点」 → 这些词没有验收口径，AI 只能自己定义，结果每次都不一样。
- 拿到结果直接复制粘贴 → 编造的数字、引用和表达一并带走。

对应三步：

|    | 步骤        | 动作                           |
| -- | --------- | ---------------------------- |
| 01 | 先写下一件小事   | 把诉求收敛成「把 X 变成 Y，用于 Z」，一次只做一件 |
| 02 | 给 AI 五样东西 | 任务、背景、输出格式、限制、示例；缺什么问什么，不编造  |
| 03 | 拿到结果别直接用  | 先让 AI 按任务卡自检一次，再由人工核查事实与表达   |

五要素的顺序和口播里略有调整，内容一致。固定套用句：

```
我要完成【任务】。
背景材料：【粘贴】。
输出格式：【格式】。
限制：【每条动词开头、可验收】。
参考示例：【一个具体样例或参照物】。
信息不够就问我，不要编造。
```

---

## 效果声明

本仓库**不承诺任何量化效果**。口播里「准确率翻了 3 倍」属于个人体感描述，没有对照实验，不作为项目结论。方法的作用是减少猜测和返工；实际效果取决于任务类型、所用模型与背景材料质量。欢迎用 `examples/` 里的案例自行验证。

## 安装

仓库根目录本身就是 Skill 目录（含 `SKILL.md`），复制整个文件夹即可。

**WorkBuddy**

```bash
git clone <你的仓库地址>
cp -r ai-task-brief ~/.workbuddy/skills/ai-task-brief
```

**支持 Agent Skills 的其他工具（Claude Code 等）**

放到对应工具的 skills 目录，例如 `~/.claude/skills/ai-task-brief/`。

**不想安装**

直接把 `assets/brief-template.md` 复制走手动填，或把 `SKILL.md` 全文粘进对话当系统指令用。

## 使用

安装后，用这些话触发：

- 「用限制帮我输出内容」
- 「按五要素任务卡帮我整理一下这个需求」
- 「套一下模板，限制怎么写才不飘」
- 「这个需求我还没想清楚，先帮我收敛成一件小事」

Skill 会依次给出：一件小事 → 五要素任务卡 → 可复制的提示词 → 第一版 → 自检记录 → 人工核查清单。只要模板或只要提示词时，直接说明即可。

**校验任务卡**（零依赖，Python 3.8+）：

```bash
python scripts/validate_brief.py examples/01-笔记转口播稿.md
python scripts/validate_brief.py 我的任务卡.md --strict
```

脚本检查五项：五个字段是否齐全、兜底句是否在、字段是否被占位文本敷衍、限制里有没有残留模糊形容词、限制条目有没有落地动词。

## 和常见 prompt 模板的区别

「角色 + 任务 + 格式」这类模板够用，但容易停在描述层。这里补了四条硬约束：

1. **限制必须可验收**：能观察 / 能测量 / 有参照物 / 有验收动作，至少满足一条。一个简单测试是「两个不同的人看同一份结果，会不会对是否达标给出同一个答案」。
2. **示例是必需字段**：一句具体样例比十行形容词更能固定输出。没有示例时要显式声明不使用，不能悄悄省掉。
3. **信息不够就问我，不要编造**：写进提示词的兜底句，也写进 Skill 的硬性规则。
4. **交付前两道核验**：AI 自检对齐任务卡，人工核查事实与表达；并明确区分两者——自检不保证真实性。

## 适用 / 不适用

**适用**：写作、改写、整理、方案草案、设计 brief、内容大纲等需要「先出第一版」的任务。

**不适用**：一次性事实问答、翻译、纯计算、格式转换等目标已经明确的请求；也不适合已经带完整验收标准的工程任务——那种情况直接做，别补流程。

## 常见问题

**为什么是五样，早期版本写的是四样？**  
四要素是任务、背景、格式、限制。口播里补上了「示例」，因为它是把审美和语气固定下来最省事的办法。本仓库以五要素为准，早期设计物料需要同步（见下方「出处」）。

**没有示例怎么办？**  
显式写「本轮不使用示例，验收以限制条目为准」。留空或让 AI 自己编一个，等于没填。

**限制写多少条合适？**  
3–6 条。太少靠猜，太多会把「第一版」憋成「终稿」。

**自检能代替人工核查吗？**  
不能。自检只回答「有没有按要求输出」，不回答「内容是不是真的」。
