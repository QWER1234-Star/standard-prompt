# 方法全解：三步 · 五要素

本文件展开口播里被一句话带过的规则，补上定义、合格标准、追问话术与失败模式。工作流见 `SKILL.md`，本文件不重复。

## 为什么是这个顺序

| 常见做法 | 问题 |
| --- | --- |
| 先挑工具，再想任务 | 工具的能力边界替你决定了任务长什么样 |
| 先写「要好看、要准确」 | 形容词没有验收口径，AI 自己定义，结果每次都不同 |
| 拿到结果才补限制 | 变成反复返工，且返工时仍说不清哪里不对 |
| 一次塞三个目标 | 每个都只做到一半，无法判断哪一版算合格 |

顺序是：先定一件小事 → 把信息补齐 → 拿到结果先核验。三步不能换。

---

## 第 1 步：收敛成一件小事

固定句式：**把 X 变成 Y，用于 Z**。

| 原始诉求 | 收敛后 |
| --- | --- |
| 帮我把笔记整理一下 | 把一段 300 字零散笔记变成 60 秒口播稿，用于抖音发布 |
| 这个页面帮我优化下 | 把落地页首屏文案改写成 3 个版本，用于 A/B 测试 |
| 帮我搞个方案 | 把上周会议记录变成一页项目启动清单，用于周一对齐 |

出现多个目标时，列成清单请用户选一个作为本轮任务，其余记为「下一轮」。不要在未收敛时推荐工具、模型或插件——那是顺序反了。

---

## 第 2 步：五要素逐字段定义

### 1. 任务

- 回答：这一轮到底要产出什么？
- 合格：一句话，含动作、对象、用途，能判断「做完没有」。
- 不合格：「优化一下」「帮我看看」「做个方案」。
- 追问：「这一轮只交付哪一个文件 / 哪一段文字？给谁用？」

### 2. 背景

- 回答：依据什么材料、给谁看、在什么场景下用？
- 合格：粘贴原始材料原文 + 一句受众说明。材料长就贴链接或附件，不要摘要后丢弃原文。
- 不合格：「就是那个项目」「你懂的」「大概是关于 AI 的」。
- 追问：「有没有原始材料可以直接贴？目标读者是谁，他已知什么？」
- 边界：背景是**已有的**，不是希望 AI 补出来的。缺材料属于「信息不够」。

### 3. 输出格式

- 回答：结果长什么样、多少、怎么分？
- 合格：可数、可检查。例：「3 个章节，每章不超过 150 字，Markdown 二级标题，末尾附 3 条待确认项」。
- 不合格：「简洁点」「排版好看」。
- 追问：「要几段 / 多少字 / 什么文件类型？有没有必须出现的小标题？」

### 4. 限制

- 回答：哪些必须满足、哪些绝对不能出现？
- 合格：每条动词开头，可验收。详细规则见 `references/constraints.md`。
- 不合格：任何形容词式愿望（更美观、更准确、专业一点）。
- 追问：「哪一条是绝对不能破的？如果只能留三条限制，留哪三条？」
- 数量：3–6 条。太少靠猜，太多会把第一版憋成终稿。

### 5. 示例

- 回答：什么算合格？给一个具体参照物。
- 合格：一段合格样例文本、一张参考图、一个已有成品链接，外加一句「照着它的什么」。
- 不合格：「参考同类爆款」（不是具体对象）、由 AI 现场编一个「示例」。
- 追问：「有没有一版你觉得接近的？贴给我，并说一句它哪里对。」
- 没有示例时：由用户显式写「本轮不使用示例，验收以限制条目为准」。这不是省略字段，是显式决策。

### 为什么比四要素多了「示例」

任务、背景、格式、限制能圈住「做什么」和「不能怎样」，但圈不住语气、审美、节奏这类只能意会的东西。一个具体样例能一次性把这几样固定下来，比堆十行形容词有效。这也是口播里「限制要写具体」最省力的落地方式：**与其描述，不如给参照物**。

## 固定套用句

```
我要完成【任务】。
背景材料：【粘贴】。
输出格式：【格式】。
限制：【限制，每条动词开头、可验收】。
参考示例：【示例】。
信息不够就问我，不要编造。
```

句尾兜底不能删。它把「猜」的代价从用户侧移到 AI 侧：宁可多问一句，也不要一个看起来完整但编出来的答案。

---

## 「不要编造」的硬边界

以下八类信息缺失时只能追问，不能推测、不能用「通常」「一般来说」带过、不能造占位内容：

1. 数字、比例、日期、时间
2. 人名、机构名、产品名、专有名词
3. 引用、出处、链接、文献
4. 原始数据、后台数据、客户材料
5. 未提供的背景事实与因果
6. 他人观点、用户没说过的立场
7. 所谓的「合格示例」
8. 验收标准本身

可以做的：把不确定的位置显式留成「待确认」，并列入人工核查清单。

## 追问话术库

| 缺失 | 话术 |
| --- | --- |
| 多个目标 | 「这几件里，本轮先交付哪一件？其余我记到下一轮。」 |
| 背景 | 「把原始材料直接贴给我就行，不用整理；另外告诉我是给谁看的。」 |
| 输出格式 | 「要几段、多少字、什么文件类型？有没有固定小标题？」 |
| 限制太虚 | 「『更美观』我没法验收。换成一条能打勾的要求，比如配色和某张参考图一致？」 |
| 限制太多 | 「现在有 9 条，先留 3 条最不能破的，其余放第二轮。」 |
| 没有示例 | 「有一版你觉得接近的吗？没有的话，明确写『本轮不使用示例』也可以。」 |
| 用户催「你别问了」 | 「好，我按现有信息出一版，并把不确定的地方标成『待确认』。」 |

一次最多问 3 个问题，优先问任务、输出格式、限制。问完仍缺的字段，显式标注「待补充」并继续，不反复打断。

## 第 3 步：两道核验

- **AI 自检**：让 AI 对照任务卡逐条打勾并修订一次。见 `references/checklist.md`。
- **人工核查**：事实、数字、引用、专有名词、表达、行动项。自检不覆盖真实性。
- **只改一次**：第二轮起先问「这次要改的是哪一条限制」，避免无限打磨第一版。

## 八类常见失败模式

| 现象 | 为什么坏 | 修正 |
| --- | --- | --- |
| 把愿望写成限制 | 「要爆款」「要高级」无验收口径 | 换成可打勾的动作或参照物 |
| 示例污染 | 让 AI 自己编示例，等于用模型既有偏好当标准 | 示例只能来自用户或真实成品 |
| 一次塞多个任务 | 无法判断哪部分算完成 | 收敛成一件，其余下一轮 |
| 把格式写成风格 | 「排版舒服」不是格式 | 写清段数、字数、标题层级 |
| 背景写成情绪 | 「这个项目挺急的」不含可用信息 | 贴原材料 + 受众说明 |
| 自检走过场 | 只回一句「已检查」 | 逐条对照五要素打勾并留记录 |
| 把自检当事实核查 | 模型无法验证自己编的数字 | 数字、引用一律进人工核查清单 |
| 过度指定 | 十几条限制让第一版失去迭代价值 | 3–6 条，先出第一版再收紧 |

---

## 关于「第一版」

口播结尾的说法是：AI 不是替你思考，是让你更快做出 MVP。这里的 MVP 指**可以拿去被人挑毛病的最小成品**，不是终稿。因此任务卡的目标是「让第一版少走一次弯路」，而不是「一次生成完美结果」。所有需要事实背书的部分，仍然留给人。
